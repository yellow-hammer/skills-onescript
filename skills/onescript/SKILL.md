# OneScript

OneScript выполняет BSL из файлов `.os` без платформы 1С. Синтаксис языка агенту известен. Здесь только то, чем пакет отличается от модуля 1С.

Отличия синтаксиса и грабли платформы: [reference.md](reference.md), [pitfalls.md](pitfalls.md). Тесты: навык `onescript-tests`.

## Каталоги пакета

```
<имя>/
  packagedef
  README.md
  LICENSE
  src/Модули/          фасад, вызов ИмяМодуля.Метод()
  src/Классы/          публичные типы, Новый ИмяКласса
  src/internal/Классы/ внутренние типы, в packagedef не объявляются
  tests/               тесты; каталог fixtures не обязателен
  examples/
  tasks/               opm run: install.os, test.os, build.os
```

Исходники в кодировке UTF-8 без BOM. Отступ в `.os` - таб.

Внутренний класс подключается из `src/Классы` и `src/Модули` так: `#Использовать "../internal"`.

## Имена классов глобальны

Имя класса уникально на весь процесс, каталог `internal` это не отменяет. `СериализаторJson` сталкивается с пакетом `jason`, `Валидатор` с `validate`, `JWT` в `crypto` с пакетом `jwt`. Имя привязывай к пакету: `СериализаторПроблем`, `HmacRfc2104`. Перед публикацией сверь имена с уже установленными библиотеками.

Модуль доступен как `ИмяМодуля.Метод()`. Класс создаётся через `Новый`.

## packagedef

Манифест без расширения, в корне. Объявляй только публичные модули и классы. Зависимости рантайма - `ЗависитОт`, тестовые - `РазработкаЗависитОт`.

```bsl
Описание.Имя("demo")
	.Версия("0.1.0")
	.Описание("Краткое описание")
	.ВерсияСреды("2.0.0")
	.ВключитьФайл("src")
	.ВключитьФайл("tests")
	.ВключитьФайл("packagedef")
	.ВключитьФайл("README.md")
	.ВключитьФайл("LICENSE")
	.РазработкаЗависитОт("1commands")
	.РазработкаЗависитОт("asserts")
	.РазработкаЗависитОт("fs")
	.РазработкаЗависитОт("oneunit")
	.ОпределяетМодуль("Demo", "src/Модули/Demo.os")
	.ОпределяетКласс("DemoValue", "src/Классы/DemoValue.os")
	;
```

Точка входа приложения, если она есть, задаётся `.ИсполняемыйФайл("src/main.os")` и в файле начинается с `#Использовать "."`.

## Библиотеки

Директива стоит в начале файла, до `Перем`:

- `#Использовать json` - пакет из `oscript_modules` или lib;
- `#Использовать "."` и `#Использовать "../src"` - каталог относительно файла.

Стандартный загрузчик: файлы из `Классы` становятся классами, из `Модули` - модулями. Имя файла без `.os` - идентификатор. То же имя стоит в `.ОпределяетМодуль` и `.ОпределяетКласс`: `#Использовать "../src"` берёт имя файла, а после `opm install` имя берётся из манифеста. Свой загрузчик - `package-loader.os` с `ПриЗагрузкеБиблиотеки`, см. [reference.md](reference.md).

Встроенных `ЧтениеJSON` / `ЗаписьJSON` хватает для JSON. Пакет `json` подключай только если он уже есть у соседнего кода.

## Команды из каталога пакета

```
opm run install    # tasks/install.os: opm install --dev -l
opm run test       # то же, что opm test: оба вызывают tasks/test.os; раннер внутри скрипта
opm run build      # tasks/build.os: opm build --out out
```

Локальный соседний пакет: `opm build`, затем `opm install -f файл.ospx`. Общего корневого `packagedef` у набора библиотек нет: каждый каталог - отдельный пакет.

В корне пакета `oscript.cfg` с строкой `lib.additional=oscript_modules`, чтобы локальные зависимости были видны интерпретатору.

## Комментарии

Комментарий в `src` объясняет грабли, без которых следующий разработчик сломает код. Не пиши, что пакет повторяет npm-библиотеку или чужой продукт. Экспортная процедура получает описание параметров и возвращаемого значения. В `examples/` допустима шапка «ПРИМЕР / Что делает / Термины». Очевидный пересказ следующей строки не пиши.

В библиотеке под внешнюю спецификацию имена модулей и классов могут быть английскими, методы и переменные русскими. В остальных пакетах имена бери как в соседних файлах.
